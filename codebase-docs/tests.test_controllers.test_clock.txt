[ PLAIN ENGLISH ]
Checks four behaviors of the clock endpoint: authentication is required, a
snapshot includes one reference timestamp and preserves requested order, unknown
codes are skipped, and a missing code query is rejected.

[ TECHNICAL ]
Four async httpx tests over GET /clock. They do not reconcile returned local
times to referenceUtc and do not directly test DST behavior or
timezone_service.build_country.

[ METHODS / SYMBOLS ]
- test_clock_requires_token: GET /clock without a bearer token -> 401.
- test_clock_returns_shared_reference_and_preserves_order: TH,JP,GB-SCT -> 200,
  referenceUtc exists, and country order is preserved.
- test_clock_skips_unknown_codes: "TH,ZZ,JP" -> [TH, JP].
- test_clock_missing_code_param_is_422: authenticated request with no `code` -> 422.

[ READS / WRITES / LOGS ]
All tests use async_client, which creates tables. Three use auth_headers, which
creates a user and exercises registration/login Redis counters. The unauthenticated
401 and missing-code 422 produce audit rows; registration/login also produce
audit rows. No test directly writes country data.

[ RELATIONS ]
Exercises: controllers.clock_routes -> services.country_service ->
           timezone_service.
Fixtures:  tests.conftest.async_client; auth_headers for three tests.

[ NOTES / GOTCHAS ]
The test names and assertions establish only the four behaviors listed above;
there is no DST or local-time reconciliation coverage. Requires the project venv
(tzdata) for zoneinfo on Windows and configured Postgres/Redis for fixtures.
