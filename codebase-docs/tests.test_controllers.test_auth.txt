[ PLAIN ENGLISH ]
These tests check the core account flows end to end: registration, password and
Google login, profile access, and that logging out really kills your ticket.

[ TECHNICAL ]
Async controller tests via the async_client fixture. Helper _register_and_login
returns a fresh token.

[ METHODS / SYMBOLS ]
- test_register_new_user .......... POST /register -> 201; response has id/
                                    created_at; no hashed_password leaked.
- test_get_personal_profile_success register+login, GET /myprofile -> 200, email
                                    matches, no hashed_password.
- test_get_personal_profile_unauthorized GET /myprofile without token -> 401
                                    "Not authenticated".
- test_logout_revokes_token ....... profile works, logout 200, then same token ->
                                    401 (denylist hit). The only test of the
                                    Redis revocation branch.
- test_logout_invalid_token ....... logout with junk token -> 401.
- test_logout_missing_token ....... logout with no token -> 401 "Not authenticated".
- test_profile_rejects_token_without_sub validly-signed access token lacking 'sub'
                                    on GET /myprofile -> 401 (dependencies no-sub branch).
- test_profile_rejects_deleted_user register+login, delete the user in-DB, then
                                     GET /myprofile -> 401 (dependencies user-is-None branch).
- test_google_login_creates_regular_user mocked verified Google credential creates
                                     a Regular user bound to `google:<sub>` and
                                     accepts the same identity again after email change.
- test_google_login_does_not_silently_link_existing_user a case-insensitive local
                                     email collision returns 409 and stays one row.
- test_google_login_rejects_invalid_credential verifier failure maps to HTTP 401.
- test_google_login_is_rate_limited_before_verification four concurrent requests
                                     admit exactly one and reject three with 429.
- test_google_login_rejects_inactive_user verified Google email cannot bypass an
                                     inactive account's HTTP 403 block.
- test_verify_google_credential_returns_verified_email mocked google-auth claims
                                     produce normalized email and stable subject.
- test_verify_google_credential_requires_verified_email an unverified claim raises
                                     InvalidGoogleCredentialError.

[ READS / WRITES / LOGS ]
Exercises the real app: writes users, sets/checks Redis denylist, and (as a side
effect) produces audit_logs rows. Registration increments Redis per-IP counters;
successful login clears its email/IP failure key. The deleted-user test directly
deletes its user row; other created users remain in the shared DB.

[ RELATIONS ]
Calls (via HTTP): auth_routes, user_routes; directly checks google_auth_service;
also dependencies.get_current_user
(no-sub / deleted-user branches). Uses conftest.async_client, core.security
(create_access_token), models.base/user_model (direct delete).

[ NOTES / GOTCHAS ]
test_logout_revokes_token depends on live shared Redis (no fake) and checks the
access-token denylist branch. Refresh-token denylist/rotation behavior is also
covered in test_refresh.py. The two tests using second-resolution timestamps for
emails can collide with existing shared-DB rows if rerun within the same second.
